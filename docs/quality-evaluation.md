# 图像生成与编辑：如何做可信的质量量化

**调查日期：2026-09-15。结论：采用有出处、可复现的分项评测协议，不把某一个数字叫作“权威认证分”。**

当前版本先完成单图编辑链路，保留原图、真实输入、每个模型的全部结果、失败及耗时。编辑实验中所有参与模型和轮次成功后才开放人工分项记录。**没有部署自动评分器、没有自动发送客户图像给视觉裁判，也没有根据少量演示图生成排行榜。**

v0.4 的“导出测评报告”是对已保存计时和人工评分的可视化汇总，并非新增自动量化评测。未评分项保留为“未评分 / N/A”，报告解析只描述记录中的事实和限制，不自动看图或补分。自动量化功能按当前决定继续暂缓。

## 1. 给当前项目的建议

在客户样本尚未准备好时，最有价值的是明确任务、保留完整证据，而不是给几张图计算 FID。

| 现在做 | 等客户样本和协议准备好再做 |
| --- | --- |
| 一个原图、一条指令，所有模型收到同一份规范化图片 | 按独立客户场景／源图分层设计评测集 |
| 明确区分文生图与图片编辑，原文与英文版本 | 固定评价问题、评审者、重复策略与可接受误差 |
| 验证所有模型的真实编辑接口，不允许退回文生图 | 多人盲评、按独立源图／prompt 分组估计置信区间 |
| 保存成功与失败、参数、原图哈希、所有输出 | 先验证自动指标与客户人评的相关性，再决定是否接入 |
| 人工分项记录保持空白，不虚构初始分数 | 只有满足数据及参考条件时才计算对应客观指标 |

**多生成同一张源图的随机变体，并不等于增加同样多的独立客户样本。** 增加样本应优先补充不同商品、人物、场景、文字与修改类型。GEditBench v2 的作者统计实现专门支持按 prompt 分组的 bootstrap，避免把相关比较当成独立数据。[9]

## 2. 常用指标到底在量化什么

| 方法 | 需要什么输入 | 能说明什么 | 主要局限／本项目采用建议 |
| --- | --- | --- | --- |
| **FID，越低越接近参考分布** | 生成图集合、匹配业务域的参考图集合 | Inception 特征的均值／协方差分布差异 | 数据集级，不是单图画质。小样本、参考域、缩放和压缩会影响解释；目前不用于客户小样本评分。[1–3] |
| **KID，越低越接近参考分布** | 两组图像特征 | 核 MMD 的无偏估计 | 无偏不等于小样本稳定；有限样本估计可为负。不是“单图版 FID”。[2–3] |
| **CLIPScore／图文相似度** | 图像与文本描述 | 粗粒度语义相关性 | 不足以准确判断数量、空间关系、字形或细节缺陷；长提示词截断和中文适配需要核对。可作辅助，不作合格线。[4,8] |
| **ImageReward** | prompt、图像 | 学习人类偏好的 reward | 训练提示词／标注分布有偏差；标准化 reward 不是百分制，也不是独立认证。[5] |
| **PickScore** | 同题候选图、prompt | 学习用户成对偏好 | 示例中的 softmax 是候选集条件概率，改变候选集合会改变数值；不能跨候选集当单图品质概率。[6] |
| **HPS v2／v2.1** | 同题图像与 prompt | 学习型人类偏好信号 | 标注人群、风格与任务覆盖有限，版本不能混用；中文商业设计应先校准。[7] |
| **GenEval** | 结构化对象、数量、颜色和关系任务 | 可拆解的指令遵循／任务通过率 | 依赖检测器、阈值和颜色分类器；自建／翻译后的任务不能直接冒称官方基准得分。[8] |
| **GEditBench v2** | 原图、编辑指令、候选编辑图 | 分开评价指令遵循、视觉质量、视觉一致性 | 很适合作为编辑评价结构的依据；具体 judge 本身仍有偏差，不能直接把其排名移植到客户域。[9] |
| **PIE-Bench** | 原图、编辑文本、区域 mask、结果图 | 编辑区和保留区的差异化评价 | mask、对齐和目标定义影响结果；缺 mask 时不应伪造区域分数。[10] |
| **LPIPS，越低越相似** | 两张对应图像／区域 | 学习到的感知距离 | 不是无参考画质。全图比较会惩罚有意修改；用于确实应该保持的区域更合适。[11] |
| **PSNR／SSIM** | 对齐的参考图与结果，必要时使用保留区 mask | 像素误差／结构相似 | 不代表编辑成功。完全不修改也可能拿最高相似度；风格、光照或布局本应变化时不能错误扣分。[10–11] |
| **OCR＋目标文本编辑距离** | 事先给定的目标文字、图中文字区域、OCR 结果 | 漏字、错字、增字等转写误差 | OCR 也会错，且不衡量美感／排版；必须人工复核，中文指令理解与中文排字要分开。[8,12] |
| **人工盲评** | 匿名结果、原图／指令、明确评价问题 | 直接判断客户任务是否满足 | 受样本、评审者与问题设计影响。小样本阶段的主要证据，但也不能宣称普遍排名。[9,12] |

### FID／KID 的正确边界

FID/KID 不需要逐张图一一配对，但两组数据的业务分布必须有意义。不能拿几张中文海报与任意自然照片集合比较，然后宣布某模型“画质优秀”。

当样本量相对于特征维数过小时，分布估计不稳定。数值正则化使计算成功，不等于结果有统计可靠性。不同图像预处理甚至 JPEG 压缩就可能明显影响 FID；Clean-FID 专门研究了这些因素。[1–3]

不设置通用的“FID 小于某值就是优秀”，也不声称某个固定数量适用于所有客户域。若将来使用，应固定参考集、样本数、特征网络、版本、缩放／裁剪／压缩方法，检查样本量变化时的稳定性。

### 为什么不把这些数都归一化后加权

CLIPScore、ImageReward、PickScore 与 HPS 的定义和标度不同：有的是余弦相似度变换，有的是训练得到的标准化 reward，有的是候选集合内的相对概率。[4–7]

把它们硬映射到百分制再平均会掩盖含义，也无法自动消除训练集和语言偏差。偏好模型可能被用于训练／优化图像模型，在该 reward 上更高不必然代表客户更满意。因此本项目编辑评价**不提供加权总分或“优秀／良好”的认证标签**。

## 3. 图片编辑应拆成什么维度

借鉴 GEditBench v2 与 PIE-Bench 的维度拆分：[9–10]

| 维度 | 人工应该看什么 | 后续可增加的量化辅助 |
| --- | --- | --- |
| **编辑指令遵循** | 改对对象了吗，属性／数量／关系是否准确，要求是否执行完整 | 预先定义的任务检查项；经人评校准的视觉裁判 |
| **结果自然度** | 改动是否自然，边缘、结构、材质、光照和阴影是否合理 | 视觉缺陷发生率；盲评胜／平／负 |
| **未改内容保持** | 不应改变的背景、物体、身份、品牌／文字是否保留 | 有有效 mask 与对齐条件时的区域 LPIPS／SSIM；身份／商品任务另行定义 |
| **文字准确性** | 应新增／替换的文字是否完全正确，应保留的文字有没有变化 | OCR＋已确认目标文本的编辑距离，并人工检查 |

当前 UI 的编辑人工记录采用上述四项，每项 1–5 分，未评／不适用留空；展示每项均值和有效样本数，不合成整体画质分数。它是内部可追溯的人评表，不冒充某论文的官方评分器。

**高保真不等于编辑成功**：原图不动可以得到最好的相似度。**有意修改也不等于失真**：例如要求替换背景时，背景变动是正确行为，而不是要被全图 SSIM 扣分的错误。

没有唯一“理想编辑后图片”也可以评价：用指令检查应改内容，用原图检查应保留内容。即使有参考结果，其他有效编辑也可能同样正确，不应该仅因不像那一张图而判失败。

Mask 也不是万能答案。需要明确有效区域归一化、边界、SSIM 窗口、LPIPS 感受野、缩放与对齐。PIE-Bench 的具体实现可用于理解其指标口径，但把非目标区简单涂黑后算全图分数不能直接叫“保留百分比”。[10–11] 全局风格修改没有明确保留区域时，相应客观指标应为 **N/A**。

## 4. 中文文字如何量化

分别设置两类题：

- **中文指令理解**：对象、颜色、数量、否定、关系、修改范围是否正确。中英等义对照只能作为诊断，不把英文输出冒充原生中文能力。
- **中文图内文字**：字形、字符、漏字／增字、可读性、排版是否符合目标。是否“看起来像汉字”不是文字正确性的合格标准。

未来可采用公开定义的归一化编辑距离：

```text
NED = Levenshtein(OCR识别文字, 目标文字) / max(两者长度, 1)
```

越低说明转写越接近。这是建议的内部定义，不是已实现或来自上述全部基准的统一标准。目标文字必须事先确定；固定 Unicode、空白、标点处理方式，不把有意义的简繁、品牌字符和数字差异消掉。OCR 结果要由人核验；文字准确不代表排版美观。

## 5. 客户样本到达后的执行协议

1. **确认授权与任务**：哪些图可发送给哪些服务、是否可公开；逐条标注应改、应保留、目标文字及可接受的输出条件。
2. **按独立源图／场景分组**：同一产品、人物或源图的多个指令／随机种子属于相关样本。调试样例与最终评价样例尽量隔离。
3. **事先固定尝试次数**：第一张输出、重复稳定性与 best-of-k 是不同实验；如果使用 best-of-k，所有模型使用相同且事先声明的 k 与选择办法。
4. **保存全部结果与失败**：成功率分母是全部尝试。质量只评价成功输出时，明确这是条件于成功的结果，不能静默删除失败模型。
5. **多人盲评**：随机化模型身份、左右位置和任务顺序；编辑题同时显示原图、指令和 A/B。允许平局，并可区分“都满足”与“都不满足”。[9,12]
6. **报告不确定性**：按独立源图／prompt 组进行配对 bootstrap，报告置信区间、有效组数和评审者数；同图重复不能充当额外独立客户案例。组数太少时，区间也无法修复覆盖偏差。[9]
7. **再校准自动指标**：检查哪些任务上自动指标与人评一致，哪些不一致。换 judge、模型版本或 rubric 后要重新校准。

不规定一个“普遍充分”的样本数。先看业务类别覆盖和 pilot 中的差异／方差，再决定需要多少独立案例，才能识别客户关心的实际差异。

## 6. 隐私、许可证与额外费用

本地指标实现不必向外发送图片，但仍需检查模型下载、遥测、日志和版本。使用开源代码不等于拥有其权重、数据集和图像的商业再分发权。

**远程视觉 LLM 裁判是一条新的数据出境／服务调用链路**：即使图像生成已获授权，也不代表客户同意把原图、编辑结果和文本发给另一个裁判服务。接入前另行确认授权、地域、数据保留与费用。GEditBench v2 的部分评测本身使用 API judge，开源框架不自动意味着全本地处理。[9]

当前自动英文准备只接收文本，不发送参考图；当前没有自动图像质量裁判。可读归档去掉连接字段仍不等于可直接公开，图像、prompt、主题和人工备注都需要审查。
